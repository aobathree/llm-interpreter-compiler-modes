# daily_brief — 高速・低トークン運用ノート

暗号通貨の日次「商い状況」分析を、**毎日・高速・低トークン**で回すための仕組みと
その設計意図をまとめる。実体は `tools/daily_brief.py`。

---

## 1. 何が問題だったか

素朴にやると、分析のたびに以下が起きる:

1. `bitbank candles` で数百本 × 複数ペアの**生ローソク足JSON**を取得
2. その JSON を **LLM（私）が文脈に読み込み**
3. SMA / RSI / MACD / ATR / 出来高統計を **LLM が手計算**

問題は 2〜3。
- 生JSONが数万トークン単位で文脈を食う（取得本数に比例して増える）
- LLM の手計算は遅く、桁ミス等の検算コストもかかる
- 毎日やると、その重い工程を毎回繰り返す

## 2. 工夫の核心：計算をスクリプトに寄せ、LLMはダイジェストだけ読む

```
[従来]  bitbank → 生JSON(数万tok) → LLMが読む＆手計算 → 要約
[改善]  bitbank → daily_brief.py が計算 → ダイジェスト10行 → LLMは10行だけ読む
```

**生JSONを一切 LLM 文脈に入れない。** LLM が読むのは最終ダイジェスト
（1ペア3行 / 全体でも数十行）のみ。取得本数を増やしても LLM のトークン消費は一定。

### 効果（実測）
- 実行時間: **約 0.44 秒**（2ペア）
- LLM が読む量: 生JSON 数万トークン → **ダイジェスト 10 行弱**
- 指標の手計算ゼロ（検算不要、桁ミスの心配なし）

## 3. 低トークン設計の具体ルール

スクリプト側で徹底していること:

- **計算は全部 Python 側**（SMA20/50/200・RSI14・MACD・ATR14・曜日別出来高・本日商い量）
- **出力は圧縮テキスト**（JSON ではなく human/LLM 両読みの1ペア3行）。
  同じ情報量なら JSON よりテキストの方がトークンが軽い
- **取得本数は用途ぴったり**に絞る（日足300＝SMA200のwarmup確保 / 時足48＝本日+前日で十分）。
  「多めに1000本」を避ける
- **確定足ベースで計算**（`meta.lastIsIncomplete` の当日足は指標から除外）し、
  当日値がブレない
- **UTF-8 固定**で Windows でも文字化けしない（再取得のやり直しが起きない）
- **ペアごとに try/except**。1ペア失敗しても全体が止まらず、その行だけ ERROR 表示

## 4. 使い方

```bash
python tools/daily_brief.py                  # 既定: btc_jpy eth_jpy xrp_jpy
python tools/daily_brief.py btc_jpy sol_jpy  # ペア指定
BITBANK_BRIEF_PAIRS="btc_jpy eth_jpy" python tools/daily_brief.py  # env で既定変更
```

前提: `bitbank` CLI が PATH にあること / Python 3.9+。

## 5. 出力の読み方（1ペア3行）

```
## btc_jpy  px=9,953,439 (+0.3% intraday)  RSI36 MACD- trend:DOWN[<S20 <S50 <S200]  ※日足未確定
   vol today(JST,so far)=84.1 | wk=120 sat=44(37%) sun=54 30d=101
   Fri 07-31(確定): 10,376,488->9,918,187 (-4.4%)  ATR14=285,768
```

| 行 | 内容 |
|---|---|
| 1行目 | 現在値・当日始値比・RSI・MACD符号・トレンド（SMAとの位置関係）・当日足の確定状態 |
| 2行目 | 本日ここまでの出来高 / 平日・土・日・30日平均（週末の薄商いが一目で分かる） |
| 3行目 | 直近確定日の値動き（始値→終値・変動率）＋ ATR14（想定変動幅＝ストップ幅の目安） |

## 6. LLM に頼むときの合言葉

「**daily brief 回して**」で、私はこのスクリプトを実行し、ダイジェスト数十行だけを読んで
必要なら一言コメントを添える。**生JSONは私の文脈に入らない。**
（この運用はプロジェクトメモリ `daily-brief-script` にも登録済み。）

指標の再手計算はしない。特定ペアの深掘り（チャート・相関・ボラ等）は
bitbank-lab-cli の各 skill 側に回す。

## 7. さらに伸ばすなら（任意）

- **定時自走**: `/schedule` でクラウド cron 化（例: 毎朝8時に実行して要約通知）
- **PowerShell ラッパー** `brief.ps1`: PATH やペア既定を固定して二重クリック実行
- **日次ログ蓄積**: 出力をファイル追記して時系列比較用データにする
- **同型の横展開**: 相関・ボラ等も「計算はスクリプト／LLMはダイジェスト」の同じ型で作れる
